# 首批诊断场景

本文件定义首批诊断场景及其判据依据。字段语义与格式规则见 [contracts.md](contracts.md)。

## 范围与来源

- **芯片**：MPC5554。寄存器定义与判据均出自 [MPC5554_RM](../knowledge/source-registry.json)，即 MPC5553/5554 Microcontroller Reference Manual（MPC5553_MPC5554_RM，Rev. 5）。
- **外设**：FlexCAN2（第 22 章）与 DSPI（第 20 章）。
- **场景来源**：**按手册构造的模拟场景**，不含真实控制器记录。对应记录的 `origin` 均为 `simulated`。
- 本批不覆盖 TMS320F28335：`knowledge/sources/` 中尚无其资料，不得借用 MPC5554 的同名外设定义。

## 取值写法与语义标注

记录把手册的位域编码写成 JSON 取值，写法与标注按以下约定处理，规则只接受在这里列明的形式。

**`FLTCONF` 的取值写法**（手册编码见 22.3.3.6，Table 22-11：`00` 错误主动 / `01` 错误被动 / `1X` 总线关闭）：

| 含义 | 本版接受的写法（大小写不敏感） |
|---|---|
| 总线关闭（`1X`） | `bus_off`、`bus-off`、`1x` |
| 错误被动（`01`） | `error_passive`、`error-passive`、`01` |
| 错误主动（`00`） | `error_active`、`error-active`、`00` |

**手册中属于 `1X` 的其它位组合（`10`、`11`）与整数编码本版不解释**：`FLTCONF` 的位宽与编码尚未逐条核对手册入知识库，按位解释没有可核对的依据。落在上表之外的取值一律报告为不支持并列出本版接受的写法，**不猜其含义，也不当成未观测**；本轮不新增编码形式或别名。其它位域的取值写法同理：只接受手册编码与场景示例中已出现的写法（如 `LOM`/`BOFFREC`/`TFUF` 等标志位取 `0`/`1`），无法解释时报不支持。

**状态位与读清除位的 `semantics` 标注**（约定见 [contracts.md](contracts.md)）：`CANx_ESR` 的 `FLTCONF`、`TXWRN` 等是状态位，须标 `instantaneous`；`BIT1ERR`～`STFERR` 是读清除位，须标 `since_last_read` 并给出覆盖区间起点。标注与手册矛盾的（例如把 `FLTCONF` 标成 `since_last_read`）属输入自相矛盾：报告矛盾并说明，**该取值不得用来确认采集时刻的状态**，同一条观测里的其它取值不受牵连。

## FC-01 总线关闭

**证据**：`CANx_ESR` 的 `FLTCONF` 为 1X。可能同时观察到 `BOFFINT` 置位、`CANx_ECR` 的 `TXECTR` 取值。

**可确认的结论**

1. 采集时刻模块处于总线关闭状态。依据 22.3.3.6 的 `FLTCONF` 编码。该结论**不需要** `CANx_CR` 佐证：`LOM` 只会把 `FLTCONF` 伪造成「错误被动」，不会伪造成总线关闭。该结论还以「该观测的 `semantics` 不是 `since_last_read`」为前提，见「取值写法与语义标注」。
2. 总线关闭期间 `TXECTR` 的语义已改变。依据 22.3.3.5：进入总线关闭时 `TXECTR` 复位为零，随后与内部计数器级联，用于计数总线上「11 个连续隐性位」的出现次数，达到 128 次时更新 `FLTCONF`。因此此时的 `TXECTR` **不是**发送错误计数，不能用于衡量历史错误严重程度。**该结论以「采集该值时模块仍处于总线关闭」为前提**：`TXECTR` 与 `FLTCONF` 来自不同的寄存器读取，契约中 `capture_id` 只表示同一次读取动作、不表示不同寄存器之间同步，所以这个前提本身需要观测（例如同一次读取中同时给出两者）才能成立；否则只能报为待确认，不能直接套用本条。
3. 若 `CANx_CR` 的 `BOFFREC` 为 1，则不会自动恢复。依据 Table 22-8：该位为 1 时禁用自动恢复，模块保持总线关闭直至该位被清除。
4. 进入总线关闭前的错误累积不可能仅来自 ACK 错误。依据 22.3.3.5：总线关闭要求 `TXECTR` 超过 255；而在只有单个节点运行的情形下，ACK 错误在模块进入错误被动后不再推高 `TXECTR`，手册据此说明该情形下「设备永远不会进入总线关闭」。

**不可推出的结论**

- **不得据此排除「总线上只有一个节点」。** 上述第 4 条的适用前提是「错误源仅为无应答」。单节点总线若同时存在位错误、填充错误等其他错误源，`TXECTR` 仍可持续累积并进入总线关闭。该结论只排除「错误源仅为无应答」这一条路径。
- 不得推断总线关闭发生的时刻，也不得推断进入总线关闭前各错误类型的分布。
- 不得由 `TXECTR` 的当前取值推断距离恢复还有多久：该值是瞬时采样，且级联计数器的相位未知；`BOFFREC` 为 1 时即使计数达到 128 也不会恢复为错误主动。
- 不得判断异常位于本节点还是总线上的其他节点。
- 不得给出终端电阻、差分电平等物理层的具体期望数值。`knowledge/sources/` 中没有总线规范，这类判据缺依据，只能作为待核实建议，并在建议中注明期望值须依据适用规范确认。

**常见缺失信息**

总线电气测量、`CANx_ESR` 错误标志位在上一次被读取的时刻（决定读清除位的覆盖区间）、`CANx_CR` 的位定时配置与总线约定波特率。

## FC-02 错误被动与只听模式歧义

**证据**：`CANx_ESR` 的 `FLTCONF` 为 01。

**判据与歧义**：依据 22.3.3.6，`FLTCONF` 为 01 表示错误被动；但同处说明，若 `CANx_CR` 的 `LOM` 置位，`FLTCONF` 会被强制显示为「错误被动」。因此：

- 记录中**缺少** `CANx_CR` 的 `LOM` 时，无法区分真实的错误被动与只听模式，应判为不可判定。
- 记录中 `LOM` 为 0 时，可确认模块处于错误被动。

**本场景未配示例，属于后续待实现示例。** 它存在的价值是：**同一个字段取值在不同配置下含义不同**，契约必须允许把「配置未知」如实表达为未知，而不是二选一。该判据已实现，`tests/test_mcu_flexcan2.py` 覆盖了三种情形：`LOM` 为 0 时确认为错误被动、`LOM` 置位时不给出错误被动结论、缺少 `LOM` 时报为不可判定。

## DS-01 DSPI 自检失败且无证据

**证据**：检测报失败，但没有 DSPI 的寄存器观测。

**为什么结论只能是「不可判定」**：第 20 章不含错误处理或故障封闭章节，因此没有故障分类与根因判据。`DSPIx_SR` 的状态位能确认若干**具体条件**（见「DSPI 可确认的具体条件」一节），但没有可据以把一次自检失败**归入某个故障状态**的规则，也不足以在「传输未启动」「传输完成但数据不符」「接收缓冲异常」之间区分。可确认具体条件与可确定故障状态是两件事，本场景缺的是后者所需的证据。

因此本场景的报告形态是：`fault_state` 与 `root_cause` 均为 `not_determined`，`confirmed_states` 与 `candidate_causes` 为空，全部内容集中在 `insufficient_data` 与 `recommended_checks`。**候选原因为空是结论，不是遗漏**：仅凭一条自检失败给出根因，属于 CLAUDE.md 明确禁止的编造判据。

## DS-02 `TFUF` 与工作模式自相矛盾

**证据**：`DSPIx_SR` 的 `TFUF` 置位，同时 `DSPIx_MCR` 的 `MSTR` 置位（主机模式）。

**判据**：依据 Table 20-6，发送 FIFO 下溢**仅对工作在 SPI 从模式的 DSPI 检测**。主机模式下出现 `TFUF` 属于输入自相矛盾。

**本场景未配示例，属于后续待实现示例。**

本场景的处置不是据此诊断，而是写入报告的 `inconsistencies`，并说明矛盾所在。**抑制范围只限于依赖矛盾数据的判断**：`TFUF` 与 `MSTR` 是矛盾的两个字段，基于它们的结论（`DS-TFUF-UNDERFLOW`）不输出；同一次读取中不依赖这两个字段的判据（RX FIFO 溢出、TX/RX 运行状态）证据独立，仍然输出。报告同时说明「该次读取整体是否自洽尚未确认」，不把保留下来的结论当作矛盾已澄清。

## DSPI 可确认的具体条件

DS-01 说明第 20 章不足以确定 DSPI 的故障状态；这不等于该章的寄存器观测什么都不能确认。Table 20-6 的标志位各自对应手册明确定义的一个条件，置位即表示该条件已经发生。本批实现以下三条：

| 条件 | 依据 |
|---|---|
| TX FIFO 下溢（`TFUF` 置位，仅对 SPI 从模式检测；主模式下置位属输入矛盾，见 DS-02） | 20.3.2.4，Table 20-6；20.4.9.4 |
| RX FIFO 溢出（`RFOF` 置位：RX FIFO 与移位寄存器都已满时又发起一次传输） | 20.3.2.4，Table 20-6；20.4.3.5.1 |
| TX/RX 运行状态（`TXRXS` 为 0 表示 STOPPED，为 1 表示 RUNNING） | 20.3.2.4，Table 20-6；20.4.2，Table 20-17 |

这些位是写 1 清除位，一次读取反映的是该位上次被清除以来是否发生过对应条件，因此结论只能说明「发生过」，不能说明发生时刻与次数。

**这些结论只确认具体条件，不确认故障状态，也不确认根因。** 第 20 章没有把上述条件归入故障分类的规则。此外，未置位不构成任何结论：某个条件未发生，不等于该外设正常或检测通过。

## 支持范围

**本批支持的结论**

- FlexCAN2 的总线关闭状态与错误主动/错误被动状态（错误被动需 `LOM` 已知且为 0）、只听模式、总线关闭期间 `TXECTR` 语义待确认这一事实、`BOFFREC` 对恢复行为的影响。
- 由 `CANx_ESR` 读清除位构成的错误标志快照，且其覆盖区间已知时。
- DSPI 的三个具体条件：TX FIFO 下溢、RX FIFO 溢出、TX/RX 运行状态。
- 输入中的自相矛盾：`TFUF` 置位与主机模式并存、状态位被标为读清除位（`FLTCONF` 标成 `since_last_read`）。
- 同一字段出现多个不同取值这一事实：本版不比较观测时刻、不做跨观测的时序分析，因此报为无法合并判断，**不挑一个取值当作当前值，也不声称这些取值来自不同采集时刻**。
- 上述结论的适用边界与不可推出项，按场景逐条列出。

**本批明确不支持**

- 物理层成因定位。缺少总线规范依据，只能给出待核实建议。
- 只给出原始寄存器值（`value`）的观测。位编号尚未入知识库，不按位解释。
- 已观测但本版没有判据的位域与寄存器。例如 `CANx_ESR` 的 `TXWRN`/`RXWRN`/`IDLE`/`TXRX`/`BOFFINT`、`CANx_ECR` 的 `RXECTR`、`DSPIx_SR` 的 `TCF`/`EOQF`：这些取值在结果中按「已观测但没有判据」列出并附观测 id，**不写成未观测，也不当成正常**。
- 手册确认存在的模块实例之外的实例名。本批只处理 `CAN_A`/`CAN_B`/`CAN_C`（22.1：MPC5554 含三个 FlexCAN2）与 `DSPI_A`～`DSPI_D`（1.5.16：MPC5554 含四个 DSPI），其余实例名按不支持报告，不假定该实例存在。
- DSPI 的故障状态与根因判据。第 20 章无对应规则。
- 总线关闭发生前的错误类型分布。
- TMS320F28335 的任何场景。资料缺失。
- 任何根因的确认（`root_cause` 首版不开放 `confirmed`）。

未列入支持范围的故障类型应明确报告为不支持，不得默认为正常。
